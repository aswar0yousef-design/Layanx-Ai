# دليل LayanX: التشغيل والاستخدام والتطوير

## التشغيل على Windows (بنقرة واحدة)

1. فك ضغط المشروع في مجلد ثابت مثل `C:\LayanX`.
2. انقر نقراً مزدوجاً على **LayanX.cmd**.
3. في أول مرة فقط يعرض المشغّل تثبيت ما ينقص (Node.js 22، وOllama، ونموذج يناسب ذاكرة جهازك)، ثم يثبّت الحزم.
4. يفتح المتصفح على صفحة **الإعداد**، ويُنشأ اختصار LayanX على سطح المكتب. بعدها يكفي النقر على الاختصار.

للإيقاف: زر **إيقاف LayanX** في صفحة الإعداد، أو **LayanX-Stop.cmd**.

السجل في `%LOCALAPPDATA%\LayanX\logs\layanx.log`، وكل بياناتك وأسرارك في `%LOCALAPPDATA%\LayanX` خارج مجلد المشروع.

## الواجهات

| العنوان | ما هي |
|---|---|
| `http://127.0.0.1:3000/setup` | الإعداد: النماذج، المفاتيح، أدوار الوكيل، المساعد، ربط الهاتف |
| `http://127.0.0.1:3000/voice` | المساعد الشخصي (جارفيس) |
| `http://127.0.0.1:3000/` | لوحة التحكم: المهام، الموافقات، سطح المكتب، حالة النظام |
| `http://127.0.0.1:3100/flow` | منشئ التدفقات لرسائل واتساب وتيليجرام |

كل الواجهات تعمل فقط بعد فتح LayanX من الاختصار مرة واحدة (يبقى الدخول 12 ساعة). هذا يمنع أي موقع في متصفحك من التحكم بالوكيل.

## المساعد الشخصي (جارفيس)

افتح **المساعد الصوتي** من صفحة الإعداد، ويُفضّل في **Microsoft Edge** لأن أصواته العربية أوضح.

- **الاستماع طوال الوقت**: فعّله، ثم ناده: «جارفيس» أو «ليان» أو «Jarvis» متبوعاً بطلبك. مثال: «جارفيس أعطني تقرير اليوم».
- **زر الدائرة**: اضغطه وتحدث بأمر واحد.
- **خانة الكتابة**: تعمل دائماً، حتى بدون ميكروفون.
- **اللغة**: زر العربية/English في الأعلى يحدد لغة السماع. الرد يكون بلغة كلامك. ويمكنك قول «تحدث بالإنجليزية» أو «speak Arabic».
- **«توقف»** أو **«stop»** يوقف الكلام فوراً.

ماذا يفعل بطلبك:

- **سؤال أو حديث**: يجيب مباشرة بالنموذج المحلي.
- **الوقت والتاريخ**: يجيب فوراً دون نموذج.
- **«تقرير» / «report»**: يلخّص مهام آخر 24 ساعة والموافقات المعلّقة.
- **طلب عمل** (برمجة، ملفات، Git، متصفح، نشر، إعلانات، بريد...): ينفّذه عبر الوكيل بكل صلاحياته وموافقاته. الإجراءات المحمية تتوقف وتنتظر موافقتك في **لوحة التحكم ← الموافقات**. المساعد لا يوافق على شيء بالصوت أبداً.

**التقرير اليومي**: في صفحة الإعداد ← المساعد الشخصي، اختر وقتاً (مثلاً 08:00). يظهر التقرير في صفحة المساعد ويمكن سماعه.

**فتح المساعد عند التشغيل**: فعّل الخيار في صفحة الإعداد، فيفتح LayanX المساعد في نافذة Edge مستقلة ويبدأ الاستماع. أبقِ النافذة مفتوحة (التصغير يكفي).

ملاحظات صادقة:

- بدون Whisper يستخدم المساعد التعرف على الكلام في Edge أو Chrome: مجاني لكنه يُعالَج على خوادم Microsoft أو Google. مع Whisper (الأقسام أدناه) يصبح كل شيء محلياً.
- إن لم يظهر صوت عربي: الإعدادات ← الوقت واللغة ← الكلام ← إضافة أصوات ← العربية.
- إن أضفت مفتاح OpenAI يظهر زر **محادثة مباشرة (OpenAI)** لمحادثة صوتية فورية (مدفوعة).

## النماذج المحلية وتبديلها تلقائياً

لا تكتب اسم نموذج في أي مكان. عند كل تشغيل يقرأ LayanX النماذج المثبتة في Ollama وقدرات كل منها (أدوات، صور، تفكير، تضمين) وحجم ذاكرة كرت الشاشة، ثم يوزّع العمل:

| نوع العمل | النموذج المستخدم |
|---|---|
| تخطيط المهام واختيار الأدوات (الوكيل) | النموذج الرئيسي الأقوى |
| ردود المساعد الصوتي | النموذج الصغير السريع |
| مهام البرمجة | نموذج البرمجة |
| قراءة الصور ولقطات الشاشة | نموذج يرى الصور (الرئيسي نفسه إن كان يدعم الصور) |

إن فشل نموذج يُجرَّب التالي تلقائياً. ويُرسل لكل نموذج حجم سياق يناسب ذاكرة كرتك حتى لا تُقطع الطلبات، ويُطفأ "التفكير" في نماذج التفكير حتى لا تتأخر الردود (لتشغيله: `LAYANX_OLLAMA_THINK=on`).

تبديل النموذج على كرت 6 غيغابايت يكلّف بضع ثوانٍ لتحميله. إن أردت نموذجاً واحداً لكل شيء: `LAYANX_OLLAMA_ROUTING=single`. ويمكنك تثبيت نموذج لمهمة معيّنة من صفحة الإعداد ← «من يقوم بأي عمل».

بعد `ollama pull` اضغط **إعادة فحص النماذج** ثم **إعادة التشغيل**.

### أفضل النماذج لجهازك (Ryzen 5 3600، GTX 1660 Super 6 GB، رام 32 GB)

ثبّت هذه الثلاثة (حوالي 15 غيغابايت):

```
ollama pull qwen3.5:9b
ollama pull qwen3.5:4b
ollama pull qwen2.5-coder:7b
```

| النموذج | الحجم | دوره عندك | لماذا |
|---|---|---|---|
| `qwen3.5:9b` | 6.6 GB | الرئيسي: التخطيط، تشغيل الأدوات، المحادثة، قراءة الصور | عربي وإنجليزي جيد، يدعم الأدوات والصور. أكبر قليلاً من 6 GB فيعمل جزء منه على المعالج والرام: أبطأ من الصغير لكنه الأدق |
| `qwen3.5:4b` | 3.3 GB | ردود المساعد الصوتي والمهام القصيرة | يعمل بالكامل على كرت الشاشة فيرد بسرعة |
| `qwen2.5-coder:7b` | 4.7 GB | البرمجة | متخصص بالكود ويعمل بالكامل على الكرت |

**مخطِّط GPT محلي (اختياري، موصى به للمهام المستقلة):** `ollama pull gpt-oss:20b` (حوالي 14 GB). هو نموذج OpenAI المفتوح، ويعمل على جهازك بدون إنترنت. يتفوق في التخطيط واختيار الأدوات، لكنه أبطأ لأن أغلبه يعمل من الرام. حين يكون مثبتاً يختاره LayanX للتخطيط تلقائياً، ويبقى `qwen3.5:4b` للردود السريعة و`qwen2.5-coder` للبرمجة. Claude لا يوجد له إصدار يعمل محلياً؛ يعمل سحابياً فقط عند الحاجة.

اختياري للبرمجة الثقيلة على مشاريع كبيرة: `ollama pull qwen3-coder:30b` (19 GB، يعمل أغلبه من الرام لأن 3.3 مليار فقط من معاملاته تعمل في كل كلمة). أبطأ في البدء ويستهلك نحو 20 GB من الرام، لذلك لا يختاره LayanX تلقائياً؛ ثبّته لمهمة «البرمجة» من صفحة الإعداد عندما تحتاجه.

لا تحمّل نماذج 27B أو أكبر للاستخدام اليومي على هذا الجهاز: ستعمل لكن ببطء شديد.

### خطط لا تنكسر

يرسل LayanX إلى Ollama مخطط JSON كاملاً للخطة (structured outputs). لا يستطيع النموذج إلا أن يختار أداة حقيقية بإجراء وصلاحية صحيحين، فقلّت الخطط المكسورة التي كانت تُصعَّد للسحابة.

- لإيقاف ذلك (لنسخة Ollama قديمة): `LAYANX_OLLAMA_STRUCTURED=off`. وعند رفض Ollama للمخطط يعيد LayanX المحاولة تلقائياً بوضع JSON العادي.
- يقلّص LayanX أجزاء الطلب المتغيرة (آخر نتيجة، الذاكرة، سياق المشروع) لتناسب سياق أصغر نموذج محلي. السبب أن Ollama يحذف **بداية** الطلب الزائد بصمت، وهي مكان التعليمات. لتحديد الحجم يدوياً: `LAYANX_PROMPT_BUDGET_CHARS`.

### إعدادات تسرّع Ollama على كرتك

نفّذ مرة واحدة في PowerShell ثم أغلق Ollama من أيقونته بجانب الساعة وأعد تشغيله:

```
setx OLLAMA_FLASH_ATTENTION 1
setx OLLAMA_KV_CACHE_TYPE q8_0
```

الأول يسرّع المعالجة، والثاني يقلل ذاكرة السياق إلى النصف تقريباً، فيبقى جزء أكبر من النموذج على الكرت. وإن شغّل LayanX برنامج Ollama بنفسه فهو يضبطهما تلقائياً.

للتأكد أين يعمل النموذج: `ollama ps`. عمود PROCESSOR يجب أن يكون `100% GPU` للنماذج الصغيرة.

ردود JSON (الخطط واختيار الأداة) محدودة بـ 1024 رمزاً: النماذج الصغيرة قد تكرر المسافات في وضع JSON حتى يمتلئ السياق، فتأخذ الخطوة الواحدة دقائق. لتغيير الحد: `LAYANX_OLLAMA_NUM_PREDICT`.

## التعرف على الكلام محلياً (Whisper)

نعم، الأفضل أن يُحوَّل صوتك إلى نص على جهازك: أدق مع العربية، ولا يخرج صوتك من الجهاز، ويعمل بدون إنترنت. التثبيت أمر واحد:

```
powershell -ExecutionPolicy Bypass -File scripts\windows\install-whisper.ps1
```

يكتشف كرت NVIDIA ويثبّت نسخة CUDA مع نموذج `large-v3-turbo` (حوالي 550 MB، يستهلك نحو 1 GB من ذاكرة الكرت). بعدها:

- `LayanX.cmd` يشغّل Whisper تلقائياً في الخلفية على المنفذ 8178.
- المساعد يستخدمه بنفسه، وتظهر في صفحة الإعداد عبارة «محلي على جهازك عبر Whisper».
- يحسب LayanX أن Whisper يشارك كرت الشاشة فيختار سياقاً أصغر للنماذج.

في صفحة المساعد ← إعدادات المساعد ← **التعرف على الكلام** تختار: تلقائي (Whisper إن كان يعمل)، أو محلي، أو المتصفح. الاستماع الدائم وكلمة الاستدعاء يعملان مع Whisper أيضاً: يلتقط المساعد كل جملة تقولها بعد صمت قصير، فإن بدأت باسمه نفّذها.

بدون كرت NVIDIA يثبّت السكربت نسخة المعالج مع نموذج `small` (أسرع لكنه أقل دقة في العربية). يمكنك الاختيار يدوياً: `-Model medium` أو `-Model large-v3-turbo`.

السكربت يثبّت نسخة محددة من whisper.cpp (البناء `b5130`) ويتحقق من بصمة SHA-256 للملف وبصمة النموذج قبل استخدامهما. لا يُثبَّت «آخر إصدار» أبداً: إصدارات whisper.cpp الأخيرة لا تحمل ملفات Windows، والملف الذي لا تطابق بصمته يُحذف فوراً.

### تفريغ عربي أدق للهجات (Cohere Transcribe Arabic، اختياري)

نموذج Cohere المفتوح للعربية (يوليو 2026) أدق بكثير من Whisper مع اللهجات: متوسط نسبة الخطأ 25.9% مقابل 36.9% لـ Whisper large-v3، وفي اللهجة الخليجية 24.4% مقابل 46.1%.

1. افتح صفحة النموذج https://huggingface.co/CohereLabs/cohere-transcribe-arabic-07-2026 وسجّل الدخول ووافق على الشروط (مرة واحدة).
2. أنشئ رمز قراءة من https://huggingface.co/settings/tokens
3. شغّل:

```
powershell -ExecutionPolicy Bypass -File scripts\windows\install-cohere-asr.ps1
```

- يطلب الرمز ويستخدمه للتحميل فقط ولا يحفظه.
- يجرّب النموذج على ملف صوتي يأتي معه. إن فشل التحميل أو التفريغ يتوقف التثبيت، ويبقى LayanX على Whisper.
- يحمّل النموذج (حوالي 4.1 GB) مثبّتاً على commit محدد، وPyTorch 2.8.0 وtransformers 5.4.0 وlibrosa 0.11.0.
- الافتراضي على المعالج (حوالي 8 GB من الرام) حتى يبقى كرت الشاشة لـ Ollama. على الكرت: `-Device cuda` (حوالي 4.5 GB من ذاكرة الكرت، دقة نصفية لأن GTX 1660 Super لا يدعم bfloat16).
- `LayanX.cmd` يشغّله على المنفذ 8181 ويستخدمه أولاً. التحميل في الذاكرة يأخذ نحو دقيقة بعد كل تشغيل.
- **إن كان Whisper مثبتاً أيضاً** يعمل بجانبه كاحتياطي: إذا كان Cohere ما زال يُحمَّل أو فشل، يفرّغ Whisper الصوت. يمكن تحديد خادم احتياطي آخر بـ `LAYANX_STT_FALLBACK_URL`.
- إن تعذّر التفريغ المحلي كله، ينتقل LayanX إلى خدمة OpenAI للتفريغ إن كانت مفعّلة.
- للرجوع إلى Whisper: `LAYANX_STT_ENGINE=whisper`. لمنفذ آخر: `LAYANX_COHERE_PORT`. لاختيار المعالج أو الكرت دون إعادة التثبيت: `LAYANX_COHERE_DEVICE=cpu|cuda`.

تنبيه: هذا النموذج لم يُختبر في CI لأن تحميله يحتاج حسابك في Hugging Face. خادمه واتصاله بـ LayanX مختبران.

### كشف الكلام ونهاية الجملة (Silero VAD وSmart Turn)

```
powershell -ExecutionPolicy Bypass -File scripts\windows\install-voice-sense.ps1
```

- **Silero VAD**: المقطع الذي لا كلام فيه (صمت أو ضجيج) لا يُرسل إلى Whisper أصلاً. يمنع ذلك أن «يسمع» Whisper كلمات في الضجيج فيستيقظ المساعد خطأً، ويوفر المعالج.
- **Smart Turn v3.2**: يعرف متى أنهيت جملتك (يدعم العربية). يرد المساعد بعد ربع ثانية من نهاية الجملة، وينتظر حتى ثانيتين إذا توقفت في منتصفها.
- يستخدم بيئة Piper إن وُجدت، وإلا ينشئ بيئة خاصة. النموذجان (حوالي 11 MB) من commit محدد مع تحقق SHA-256، والخادم يرفض أي ملف تغيّرت بصمته.
- `LayanX.cmd` يشغّله على المنفذ 8180 (`LAYANX_VOICE_SENSE_PORT`)، أو عنوان آخر بـ `LAYANX_VOICE_SENSE_URL`.

**كلمة الاستدعاء:** في وضع «الاستماع طوال الوقت» يُفرَّغ كل مقطع فيه كلام عبر Whisper أو Cohere، فإن بدأ باسم المساعد نُفّذ ما بعده. لا يحتاج ذلك تدريب نموذج خاص، ويعمل مع أي اسم تكتبه في إعدادات المساعد. القائمة الافتراضية فيها «ليان» و«ليين» (كما يكتبها Whisper أحياناً) و«جارفيس».

## صوت عربي طبيعي محلي (Piper)

بدل أصوات المتصفح، يمكن أن يرد المساعد بصوت عربي طبيعي يعمل على جهازك:

```
powershell -ExecutionPolicy Bypass -File scripts\windows\install-piper.ps1
```

- يحتاج Python من 3.10 إلى 3.13، ويعرض تثبيت Python 3.12 عبر winget إن لم يجده.
- يثبّت `piper-tts` بالإصدار 1.8.0 في بيئة خاصة به، مع الصوت العربي `ar_JO-kareem-medium` والإنجليزي `en_US-lessac-medium` (حوالي 60 MB لكل صوت). أضف `-NoEnglish` للعربي فقط.
- `LayanX.cmd` يشغّله في الخلفية على المنفذ 8179، والمساعد يستخدمه تلقائياً.
- يُختار الصوت حسب لغة الرد. لتغيير الصوت: `LAYANX_TTS_VOICE_AR` و`LAYANX_TTS_VOICE_EN`. لخادم في مكان آخر: `LAYANX_TTS_BASE_URL`.
- إن توقف Piper يعود المساعد لصوت OpenAI (إن كان مفعّلاً) ثم لصوت المتصفح.

Piper رخصته GPL-3.0، لذلك يعمل كبرنامج منفصل ولا يُدمج كوده في LayanX.

**المقاطعة:** مع Whisper المحلي، إذا بدأت بالكلام وهو يرد يتوقف فوراً ويسمعك. يعتمد ذلك على إلغاء صدى الميكروفون في المتصفح؛ مع السماعات العالية جداً استخدم سماعة رأس.

`stop.ps1` يوقف Whisper وPiper مع LayanX لتحرير ذاكرة كرت الشاشة.

## Claude وOpenAI وGemini للمهام الصعبة

صفحة الإعداد ← **مفاتيح الخدمات**: احفظ `ANTHROPIC_API_KEY` أو `OPENAI_API_KEY` أو `GEMINI_API_KEY`. ثم في قسم **الذكاء السحابي**:

1. اضغط **اختبار وعرض النماذج**: يتأكد من المفتاح ويعرض النماذج المتاحة لحسابك فعلاً، فتختار منها.
2. اختر السياسة:
   - **محلي فقط**.
   - **محلي أولاً والسحابة عند الفشل** (الافتراضي): إن فشل النموذج المحلي في التخطيط أو تعطل، يأخذ السحابي نفس المهمة قبل تنفيذ أي أداة.
   - **السحابة للمهام المعقدة مباشرة**: المهام الطويلة أو متعددة الخطوات أو المعمارية تذهب للسحابة من البداية.
3. **إعادة التشغيل**.

ويمكنك طلب نموذج بالاسم في أي مهمة: «استخدم كلود لكتابة خطة المشروع» أو «use GPT to review this». وفي لوحة التحكم قائمة بجانب زر التشغيل: تلقائي، محلي أولاً، Claude، GPT، Gemini.

النماذج الافتراضية: `claude-sonnet-5-5`، `gpt-5.6-terra`، `gemini-3.6-flash`. للمهام الأصعب اختر `claude-opus-5-5` أو `gpt-5.6-sol`. التكلفة على حسابك لدى كل مزود.

### حد الإنفاق الشهري وتوجيه يتعلم

- **حد شهري:** صفحة الإعداد ← الذكاء السحابي ← **حد الإنفاق الشهري**.
  - اكتب حداً بالدولار مع سعر كل مليون رمز لكل مزود (من صفحة أسعاره)، أو حداً بعدد الرموز فقط.
  - عند بلوغ الحد تتوقف السحابة ويكمل LayanX بالنماذج المحلية حتى الشهر التالي.
  - الاستهلاك يظهر في نفس الصفحة، ومتاح عبر `GET /v1/cloud/usage`.
  - الإعدادات المقابلة: `LAYANX_CLOUD_MONTHLY_BUDGET_USD`، `LAYANX_CLOUD_MONTHLY_TOKENS`، `LAYANX_PRICE_ANTHROPIC_IN`/`_OUT` (ومثلها لـ OPENAI وGEMINI).
- **توجيه يتعلم من تاريخك:** إذا فشل النموذج المحلي مرتين في التخطيط لمهام متشابهة، تذهب المهمة المشابهة التالية إلى السحابة مباشرة دون محاولة محلية بطيئة. أول نجاح محلي يعيدها للمحلي. يعمل فقط إذا سمحت سياسة السحابة بذلك.

## التحكم من أي مكان (الهاتف خارج المنزل)

الطريقة الآمنة الموصى بها: **Tailscale**، شبكة خاصة مشفّرة بين أجهزتك، مجانية للاستخدام الشخصي، ولا تفتح أي منفذ على الإنترنت.

1. على الكمبيوتر: `winget install Tailscale.Tailscale` ثم سجّل الدخول.
2. على الهاتف: ثبّت تطبيق Tailscale وسجّل الدخول بنفس الحساب.
3. صفحة الإعداد ← **التحكم من أي مكان** ← فعّله ← **إعادة التشغيل**.
4. اضغط **تفعيل العنوان الآمن (HTTPS)**. يعطيك عنواناً مثل `https://my-pc.tail1234.ts.net`. إن طلب Tailscale تفعيل شهادات HTTPS، افتح الرابط الذي يظهر ووافق.
5. أنشئ رمز ربط وأدخل هذا العنوان في التطبيق.

بعد الربط يعرف التطبيق كل عناوين جهازك (البيت وTailscale) ويختار ما يعمل تلقائياً. وتبقى الحماية كما هي: الهاتف يحتاج مفتاحه الخاص، ولا تعمل الجلسات أو مفتاح المالك عبر الإنترنت، وصفحة الإعداد لا تفتح إلا من الكمبيوتر نفسه.

بديل متقدم: نفق مثل Cloudflare Tunnel يوجّه إلى `http://127.0.0.1:3000`، وأضف اسمه في `remoteHosts` داخل `%LOCALAPPDATA%\LayanX\settings.json`.

## لوحة التحكم

`http://127.0.0.1:3000/` لوحة قيادة واحدة تراقب منها كل شيء، بالعربية أو الإنجليزية (زر EN / ع أعلى الصفحة):

- **الأعلى**: خانة «اطلب من LayanX أي شيء» وزر الميكروفون، وحالة الوكيل، وجرس الموافقات المعلّقة.
- **الأرقام**: المهام النشطة، نسبة النجاح لآخر 30 يوماً، المهام المكتملة، التطبيقات المتصلة.
- **الوكيل الذكي**: اكتب المهمة وتابع خطواتها ومخرجاتها مباشرة، ووافق أو ارفض من نفس المكان. بجانبه: المهمة الحالية بشريط التقدم، وآخر الأنشطة.
- **سطح المكتب والطرفية**: لقطة للشاشة أو بث مباشر، وأوامر مسموحة (`git status`، `npm test`، `npm run build`…) تعمل في مجلد المشروع بعد موافقتك.
- **إجراءات سريعة**: فتح المشروع في VS Code، تشغيل الاختبارات، البناء، إنشاء فرع.
- **بطاقات القدرات ومعمارية النظام** بحالتها الحقيقية.

وفي القائمة الجانبية أقسام كاملة: المهام، الموافقات، الطرفية، المشاريع والكود (وربط أي مجلد)، Git، التجارة، التواصل، الإعلانات، التحليلات، التكاملات، فريق الوكلاء، الجدولة، النماذج، الأدوات، النشاط، الإعدادات.

## المهام المستقلة (حتى النهاية دون متابعة)

من لوحة القيادة فعّل زر **حتى النهاية** بجانب خانة الوكيل، أو افتح **المهام المستقلة**، أو من الهاتف، أو من VS Code بالأمر **LayanX: Finish a Goal Autonomously**. يقوم المشرف بما يلي:

1. **مواصفات**: يحوّل طلبك إلى معايير قبول ومراحل صغيرة، ويقرأ ملاحظات المشروع السابقة.
2. **خط أساس**: يثبّت الحزم ويشغّل الاختبارات والبناء **قبل** أي تعديل.
3. **المراحل**: كل مرحلة يتولاها الوكيل المناسب: المبرمج، أو المختبِر، أو الباحث، أو مشغّل سطح المكتب، أو الأعمال.
4. **بوابات**: بعد كل مرحلة يجب أن تنجح الاختبارات والبناء، **ولا يُقبل أن يفشل شيء كان ينجح قبلها**.
5. **الإصلاح**: يعيد الخطأ للوكيل. في المحاولة الثالثة يستعين بوكيل برمجة (Aider محلياً)، ثم بنموذج سحابي إن سمحت السياسة. يتوقف بعد 4 محاولات ويشرح السبب.
6. **فحص بصري** للواجهات: يشغّل خادم التطوير، ويفتح الصفحة في Edge على الحاسوب والهاتف، ويجمع الأخطاء ومشاكل الوصول، ويقارن بصورة مرجعية. ثم يحكم نموذج الرؤية هل الشاشة تطابق المطلوب.
7. **نقطة رجوع**: commit بعد كل مرحلة ناجحة.
8. **ملاحظات المشروع**: يكتب `.layanx/PROJECT.md` و`.layanx/CHANGELOG.md` داخل المشروع، فالعمل التالي يبني عليها ولا يعيد البناء.

حدود كل مهمة: ساعتان و30 جولة افتراضياً، وتستطيع تغيير ذلك. وتستمر المهمة بعد إعادة تشغيل LayanX.

**متابعة المهمة ومعرفة انتهائها:**
- **«أكمل المهمة»:** زر يظهر على المهمة التي توقفت (فشلت، أو أُلغيت، أو انتهى وقتها)، في صفحة «المهام المستقلة» وفي المحادثة. يكمل من المرحلة التي توقفت عندها، ولا يعيد المراحل المنتهية، ويبدأ الوقت والجولات من جديد.
- **إذا كتبت رسالة والمهمة تعمل على نفس المشروع** يسألك LayanX أولاً: «موافق» يضيف رسالتك تعليمات للمهمة الجارية، تُتبع من الخطوة التالية. «إلغاء» ينفّذها كطلب جديد. لن تبدأ مهمة ثانية دون علمك.
- **«افتح الموقع عند الانتهاء»:** خيار في صفحة المهام المستقلة، مفعّل افتراضياً. ويفهمه LayanX أيضاً من رسالة مثل «افتحه عند الانتهاء» أو «when finished open it». عند نجاح الفحص النهائي يبقى خادم التطوير يعمل، ويُفتح الموقع في متصفح هذا الكمبيوتر. لإيقاف الفتح التلقائي: `LAYANX_OPEN_BROWSER=off`.
- **زر «افتح الموقع»** على أي مهمة مكتملة: يشغّل خادم التطوير إن لم يكن يعمل (بموافقتك إن كان المشروع «مراقَباً») ثم يفتحه.
- **كيف تعرف أنها انتهت كلها:** المهمة المكتملة يظهر عليها «✓ اكتملت وتحققت: 6/6 مراحل» وما أثبت ذلك (الاختبارات، والبناء، والفحص البصري). المهمة المتوقفة يظهر عليها «توقفت عند المرحلة 3: …» والسبب.
- **مشروع جديد يبدأ من مجلد فارغ:** بعد أن ينشئ الوكيل `package.json`، يضيف LayanX فحوص المشروع (التثبيت، والاختبار، والبناء، والفحص البصري) تلقائياً، فلا تُعلَن المهمة منتهية دون إثبات.

**حالة الجهاز في لوحة القيادة:** بطاقة تتحدث كل 3 ثوانٍ، فيها:
- نسبة المعالج، والذاكرة المستخدمة من الكلية.
- استخدام كرت الشاشة وذاكرته (عبر `nvidia-smi` الذي يأتي مع تعريف NVIDIA).
- النماذج التي يحملها Ollama الآن، وكم منها على الكرت وكم في الرام.

إن كان جزء كبير من النموذج في الرام بدل الكرت فالردود أبطأ. حينها استخدم نموذجاً أصغر للمهمة، أو أوقف خدمات الصوت التي تشارك الكرت.

### مستوى الثقة لكل مشروع

من **المشاريع والكود** اختر لكل مشروع:

- **مراقَب** (الافتراضي): يسأل قبل كل إجراء خطر.
- **موثوق**: ينفّذ وحده ما يمكن التراجع عنه داخل المشروع: تعديل الملفات، والتثبيت، والاختبار، والبناء، وخادم التطوير، وcommit والفروع المحلية، واختبار المتصفح، ووكيل البرمجة المحلي. **هذا ما يجعله ينهي المهمة دون متابعة.**
- **كامل**: يضيف التحكم بالشاشة ووكلاء البرمجة السحابيين.

في كل المستويات تبقى بحاجة لموافقتك على: `git push`، والنشر، وإرسال البريد، والإعلانات، والتداول.

### وكلاء البرمجة الإضافيون

يكتشفها LayanX تلقائياً ويختار بينها، وتظهر في **فريق الوكلاء**:

- **Aider** (محلي، يستخدم `qwen2.5-coder` عندك): `python -m pip install aider-install` ثم `aider-install`.
- **Claude Code** (سحابي، يحتاج حساب Anthropic): `npm install -g @anthropic-ai/claude-code`.
- **OpenAI Codex** (سحابي): `npm install -g @openai/codex`.

السحابيان لا يُستخدمان إلا إذا كانت سياسة السحابة تسمح، وبعد فشل المحاولات المحلية. وLayanX يعيد الاختبارات بعد كل وكيل، ولا يصدّق قوله «انتهيت» دون فحص.

## ذاكرة المشروع ولوحة المشروع والأمان

### ذاكرة داخل كل مشروع (`.layanx/`)

تنتقل مع الكود، ويقرؤها LayanX قبل كل مهمة، فيبني على الموجود ولا يعيد البناء:

| الملف | ما فيه |
|---|---|
| `PROJECT.md` | هدف المشروع وقواعده. اكتب فيه ما يجب أن يحترمه الوكيل |
| `ARCHITECTURE.md` | خريطة تُحدَّث تلقائياً: المجلدات، ونقاط البدء، والسكربتات، وأكبر الملفات، وأسماء الملفات المكررة. ما تكتبه أنت خارج الجزء التلقائي يبقى |
| `DECISIONS.md` | لماذا اختير كل حل. الوكيل يضيف ولا يمحو |
| `KNOWN_ISSUES.md` | المشاكل المفتوحة والمحلولة. كل مهمة فشلت تُسجَّل هنا تلقائياً |
| `CHANGELOG.md` | كل مهمة مستقلة وما غيّرته |
| `health.json` و`security.json` | آخر نتيجة للاختبارات والبناء والأمان والفحص البصري |

### لوحة المشروع

من القائمة: **لوحة المشروع**، أو زر «لوحة المشروع» بجانب أي مشروع. فيها:

- صحة المشروع: الاختبار، والبناء، والأنواع، والفحص، والأمان، والفحص البصري، ومتى آخر مرة.
- المشاكل المعروفة، مع زر **أصلحها** الذي يبدأ مهمة مستقلة بالسياق كاملاً.
- نتائج الأمان، مع زر إصلاح لكل ملاحظة خطيرة.
- القرارات، وسجل التغييرات، وخريطة المشروع، وآخر commits والفرع الحالي، ولقطات الواجهة، وآخر المهام.
- **مراجعة الكود والأمان** لآخر commit في هذا المشروع وحده.

### لا يعمل على main مباشرة

إذا كان المشروع على فرع `main` أو `master`، ينشئ المشرف فرعاً لكل مهمة (`layanx/التاريخ-…`)، فيبقى main سليماً لو حدث خطأ. أنت تدمج حين ترضى.

### أمان ما يصنعه

قبل أن يعتبر أي مهمة منتهية يفحص المشروع:

- **الكود**: مفاتيح مكشوفة، وحقن أوامر وSQL، وXSS، وإيقاف فحص الشهادات، وCORS مفتوح، وcookies غير محمية، وأسرار JWT ثابتة، وتشفير ضعيف، ووضع debug، وملف `.env` غير مستثنى من Git.
- **الحزم**: `npm audit`.
- **الموقع المشغّل على جهازك**: فحص على طريقة OWASP ZAP. يزور حتى 20 صفحة من الموقع نفسه ويفحص كل رد دون مهاجمته:
  - ترويسات الأمان، وجودة CSP (`unsafe-inline` و`unsafe-eval` والمصادر المفتوحة)، والحماية من التأطير.
  - cookies بلا HttpOnly أو Secure أو SameSite، وCORS يقبل أي موقع.
  - ظهور تفاصيل الأخطاء الداخلية، وكشف إصدار الخادم، وسكربتات خارجية بلا Subresource Integrity.
  - ملفات لا يجوز نشرها، مثل `.env` و`.git`.
  
  لا يفحص إلا العناوين على جهازك (localhost و127.0.0.1).
- **ZAP الحقيقي (اختياري)**: إذا كان Docker يعمل، يشغّل LayanX فحص ZAP baseline من صورة بإصدار ثابت (`ghcr.io/zaproxy/zaproxy:2.17.0`) ويضيف ما يجده. الافتراضي `LAYANX_ZAP=auto`: يُستخدم فقط إن كانت الصورة محمّلة. `LAYANX_ZAP=on` يحمّلها مرة واحدة (حوالي 1.5 GB)، و`off` يوقفه. صورة أخرى: `LAYANX_ZAP_IMAGE` بإصدار ثابت.

النتيجة درجة من 100. **أي ملاحظة حرجة أو عالية تمنع التسليم** وتُرسل للمبرمج ليصلحها، ثم يُعاد الفحص. لتجاهل سطر راجعته بنفسك، أضف في آخره تعليقاً فيه `layanx-ignore-security`.

## العزل والدمج (المرحلة 3)

### أين تعمل أوامر المشروع

من **لوحة المشروع** اختر مستوى العزل لكل مشروع:

| المستوى | ماذا يعني |
|---|---|
| **محلي** (الافتراضي) | على جهازك، ببيئة نظيفة لا تحتوي أسرار LayanX |
| **محلي بدون سكربتات التثبيت** | مثل السابق، لكن `npm install` لا يشغّل سكربتات الحزم. يمنع أشهر هجمات سلسلة التوريد (`postinstall` خبيث) |
| **مقيّد** (Windows، دون Docker) | دون سكربتات تثبيت، والأوامر لا تكتب إلا داخل مجلد المشروع (ولا تلمس `.git`)، ولها حد للذاكرة والعمليات |
| **Docker (معزول)** | كل شيء داخل حاوية تُحذف بعد الاستخدام |

**العزل المقيّد** يحمي جهازك دون Docker ودون صلاحيات مدير. يعمل كل أمر بمستوى سلامة منخفض (Low integrity)، فيرفض Windows كتابته في ملفاتك الشخصية وبيانات LayanX والمشاريع الأخرى:
- يُعلَّم مجلد المشروع ومجلدات العزل المؤقتة وحدها بمستوى منخفض حتى يكتب فيها. يبقى `.git` بمستوى متوسط، فلا يستطيع سكربت زرع hooks يشغّلها LayanX لاحقاً.
- **إن استبدل أمرٌ مجلد `.git`** (أعاد تسميته ووضع غيره) أو أنشأ واحداً جديداً، ينقل LayanX الدخيل جانباً باسم `.git-untrusted-…`، ويعيد الأصلي بعد التعرف عليه من بصمته، ويذكر ذلك في نتيجة المهمة.
- **أوامر git التي يشغّلها LayanX نفسه** في هذه المجلدات تعمل دون hooks ودون fsmonitor. سبب ذلك أن hooks مثل husky وlefthook ملفات داخل المشروع يستطيع الأمر المعزول تعديلها.
- **لا يشغّل LayanX أوامر git في المشروع** في حالتين:
  - إن استُبدل `.git` أثناء عمل أمر معزول، مثل خادم تطوير ما زال يعمل. التشغيل التالي في المشروع يعيد الأصلي.
  - إن ظهر `.git` لم يفحصه LayanX من قبل وإعداداته تشغّل برامج: filters أو drivers أو helpers أو include.
  
  ملاحظة: إعداد git-lfs المحلي من هذا النوع. للمشاريع التي تحتاجه اختر Docker أو «محلي بدون سكربتات». أما husky (`core.hooksPath`) فيعمل عادياً، لأن LayanX يلغي الـ hooks في أوامره أصلاً.
- **لكل مشروع مجلداته المؤقتة الخاصة** (temp وcache وhome)، فلا يستطيع مشروع معزول تسميم ذاكرة حزم مشروع آخر أو إعداداته. لذلك تُحمَّل الحزم مرة لكل مشروع.
- **مشروع ثُبّتت حزمه بـ pnpm** يرتبط بمخزن pnpm المشترك. يرفض LayanX تعليمه حتى لا يصبح المخزن المشترك قابلاً للكتابة، ويطلب حذف `node_modules` مرة واحدة. بعدها تُثبَّت الحزم بمخزن خاص بالمشروع.
- **بيانات LayanX** (الخزنة، والجلسات، وروابط الدخول، والسجلات) تُعلَّم بحيث لا يقرؤها الأمر المعزول. بدون ذلك كان يستطيع قراءة رمز الدخول والتحكم في LayanX عبر واجهته المحلية.
- **كل الأدوات تحترم العزل:** `project.run`، و`project.verify`، و`npm test` من الطرفية، وتثبيت الحزم بـ `project.bootstrap`، ووكلاء البرمجة.
- بدون صلاحيات، ومجموعة المدير معطلة إن وُجدت.
- Job Object: حد للذاكرة (نفس `LAYANX_DOCKER_MEMORY`، الافتراضي 4g)، وحتى 256 عملية. إيقاف المهمة يوقف كل ما شغّلته.
- **حدوده:**
  - لا يمنع قراءة ملفاتك الأخرى ولا الإنترنت؛ Docker يمنعهما.
  - المشاريع المعزولة بهذا المستوى تستطيع الكتابة في بعضها. لا تضع مشروعاً لا تثق به بجانب مشروع مهم بهذا المستوى؛ استخدم Docker له.
  - الحزم المحلية `file:` التي تشير خارج مجلد المشروع لا تعمل فيه عمداً.
  - Flutter غير مدعوم فيه، لأنه يكتب في مجلد SDK الخاص به.
- عند تغيير مستوى المشروع من «مقيّد» إلى غيره، أو فك ربط المجلد، يعود المجلد لمستواه العادي.
- أول استخدام على مشروع كبير يأخذ لحظات لتعليم الملفات، ثم يُتذكَّر.
- يُجمَّع المشغّل الصغير مرة واحدة بمترجم .NET الموجود في Windows.
- وكلاء البرمجة الخارجيون في هذا الوضع يعملون داخله أيضاً، ولهم مجلد home خاص بهم.

في وضع Docker يحدث التالي:
- الحاوية لا ترى إلا مجلد المشروع.
- بدون صلاحيات إضافية، مع حدود للذاكرة والمعالج والعمليات.
- **بدون إنترنت أثناء الاختبار والبناء**؛ الإنترنت مسموح فقط أثناء التثبيت.
- `node_modules` في مساحة خاصة بالحاوية، فلا تختلط حزم Linux بحزم Windows.
- خادم التطوير ينشر منفذه على `127.0.0.1` فقط.

يحتاج Docker Desktop مثبتاً وشغالاً. للسماح بالإنترنت أثناء الاختبارات: `LAYANX_SANDBOX_NETWORK=on`.

### إرجاع العمل إلى main

كل مهمة مستقلة تعمل على فرعها الخاص. في **لوحة المشروع** يظهر قسم الفروع غير المدموجة، ولكل فرع زران:

- **دمج**: دمج محلي في main مع `--no-ff`. إذا وُجد تعارض يُلغى الدمج ولا يتغير شيء.
- **نشر PR**: يرفع الفرع ويفتح Pull Request على GitHub (يحتاج `GITHUB_TOKEN`)، أو يعطيك رابط المقارنة.

الدمج يحتاج موافقتك إلا في مستوى الثقة «كامل»، والنشر يحتاج موافقتك دائماً.

## التعلم الذاتي والمهارات (المرحلة 4)

صفحة **التعلم والمهارات** في القائمة.

### أدلة العمل (Playbooks)

أدلة مكتوبة لنوع معيّن من المهام: الخطوات، والأخطاء الشائعة، وطريقة الاختبار. يختار المشرف أنسبها لكل مهمة ويقرؤها قبل التخطيط. مصادرها:

- **مدمجة**: 11 دليلاً، منها React وVite، وNext.js، وNode API، وFastAPI، وFlutter، وصفحات الهبوط وSEO، والمتاجر، والمحتوى، وإصلاح الأخطاء، والواجهات العربية، وأساسيات الأمان.
- **متعلَّمة**: بعد مهمة احتاجت عدة مراحل أو إصلاحات، يكتب LayanX دليلاً للمرة القادمة. **يبقى مقترحاً حتى توافق عليه.**
- **من البحث**: إذا احتاجت المهمة تقنية لا يغطيها دليل ولا ذاكرة المشروع، تكون أول مرحلة «بحث». يقرأ فيها التوثيق الرسمي ويكتب دليلاً داخل المشروع. يُفحص الدليل أمنياً، ويُستخدم في هذا المشروع، وتنتظر نسخته العامة موافقتك.
- **مهارات بصيغة SKILL.md** (صيغة agentskills.io التي تستخدمها Claude وCodex وغيرها):
  - يقرأ LayanX المجلدات `.layanx/skills` و`.claude/skills` و`.agents/skills` داخل المشروع، و`skills` في مجلد بياناته (`LAYANX_SKILLS_DIR`).
  - يُفحص **كل ملف** داخل مجلد المهارة، لا ملف SKILL.md وحده، لأن التعليمات قد تطلب تشغيل سكربتاتها.
  - زر **تصدير كمهارة** يحوّل أي دليل معتمد إلى مجلد SKILL.md يمكنك استخدامه في أدوات أخرى.

**الحجر الصحي:** أي دليل أو مهارة جاءت مع ملفات المشروع (مستودع نسخته، أو مهارة نزّلتها) تبقى «بانتظار الموافقة» ولا تُستخدم حتى توافق عليها. الموافقة مرتبطة ببصمة المحتوى، فأي تعديل لاحق يعيدها للحجر. وحدها الأدلة التي كتبها بحث LayanX نفسه أثناء مهمة تُستخدم مباشرة في ذلك المشروع.

السبب: في 2026 نُشرت مئات المهارات الخبيثة في سوق مهارات OpenClaw. كانت تطلب «متطلبات مسبقة» تنزّل برنامجاً لسرقة كلمات المرور. يكشف الفحص الآن:
- روابط مواقع اللصق وعناوين IP المباشرة.
- أدوات التنزيل في Windows (`certutil` و`bitsadmin` و`mshta`).
- فك الترميز ثم التشغيل.
- استثناءات Defender.
- الأرشيفات المحمية بكلمة مرور.
- الحروف المخفية وحروف عكس الاتجاه.

كل دليل يُفحص ضد التعليمات الخبيثة (مثل «تجاهل التعليمات» أو تسريب المفاتيح أو `curl | sh`). يُحسب نجاح كل دليل، ويُوقف تلقائياً إذا استُخدم 5 مرات بنجاح أقل من 40%.

### الدروس

- **درس إصلاح**: حين تفشل مرحلة ثم تنجح، يسجّل LayanX ما أصلحها، مربوطاً ببصمة الخطأ. إذا ظهر نفس الخطأ لاحقاً، حتى بملفات وأرقام مختلفة، يأخذ الوكيل الإصلاح المعروف مباشرة.
- **درس تجنّب**: حين تتوقف مهمة، يُسجَّل النهج الذي لم ينجح.

يمكنك البحث في الدروس وحذف أي درس من الصفحة.

**لا شيء مما يتعلمه ينفّذ كوداً بنفسه.** الأدلة والدروس نصوص يقرؤها المخطِّط، وكل تنفيذ يمر بالصلاحيات والموافقات والاختبارات وبوابة الأمان.

## أدوات إضافية عبر MCP

MCP بروتوكول مفتوح لخوادم الأدوات. يعمل LayanX **عميلاً** له، فيستطيع الوكيل استخدام خوادم مثل Playwright MCP وقواعد البيانات وFigma وJira دون إعادة كتابتها.

- لوحة التحكم ← **التكاملات** ← **خوادم أدوات MCP**: ابحث في السجل الرسمي `registry.modelcontextprotocol.io`، ثم **أضف**، ثم **موافقة وتشغيل**.
- كل خادم جديد يبقى معطلاً حتى توافق عليه، والموافقة متاحة لك فقط ومن هذا الجهاز فقط.
- لا يُقبل إلا إصدار محدد (`pkg@1.2.3` أو `pkg==1.2.3` أو `image:1.2.3`)، و«latest» مرفوض.
- أدوات الخادم تظهر بأسماء `mcp.<الخادم>.<الأداة>`. كل استدعاء لها يحتاج موافقتك، إلا الأدوات التي تعلّمها آمنة (للقراءة فقط).
- الخادم لا يرى أسرار LayanX. يأخذ فقط الأسرار التي تسمّيها له في `envFromSecrets`.
- يستطيع الوكيل البحث في السجل (`mcp.registry.search`) و**طلب** خادم (`mcp.server.request`)، لكن الطلب يبقى بانتظار موافقتك.
- العميل يدعم الإصدار الحديث للبروتوكول `2026-07-28` والإصدارات الأقدم حتى `2024-11-05`، عبر stdio وStreamable HTTP. لاستخدام سجل آخر: `LAYANX_MCP_REGISTRY_URL`.

## فحص أمني بأدوات خارجية (اختياري)

```
powershell -ExecutionPolicy Bypass -File scripts\windows\install-security-tools.ps1
```

يثبّت ثلاث أدوات بإصدارات محددة، ويتحقق من بصمة SHA-256 المنشورة لكل منها قبل استخدامه:

| الأداة | الإصدار | ما تفحصه | الرخصة |
|---|---|---|---|
| gitleaks | 8.30.1 | الأسرار المكشوفة في الملفات | MIT |
| osv-scanner | 2.6.0 | ثغرات الحزم في npm وPyPI وDart وNuGet | Apache-2.0 |
| opengrep | 1.30.1 | أنماط الكود الخطرة، بقواعد LayanX في `config/opengrep-rules.yml` | LGPL، تعمل كبرنامج منفصل |

- مجلد الأدوات: `%LOCALAPPDATA%\LayanX\tools\bin`، ويمكن تغييره بـ `LAYANX_TOOLS_DIR`.
- إذا استُبدل ملف أداة بعد تثبيته لا يُستخدم.
- يدمج `project.security` نتائجها مع فحصه الداخلي.
- للإيقاف: `LAYANX_EXTERNAL_SCANNERS=off`. لقواعد Opengrep خاصة بك: `LAYANX_OPENGREP_CONFIG`.

## المهام المتوازية ووكلاء البرمجة في Docker

- **مهمة واحدة لكل مشروع في الوقت نفسه.** المهمة الثانية على نفس المشروع تنتظر (حالة «في الانتظار») حتى تنتهي الأولى، حتى لا يعدّل وكيلان نفس الملفات والفرع معاً. المهام على مشاريع مختلفة تعمل بالتوازي.
- **إذا كان المشروع معزولاً في Docker** يعمل وكيل البرمجة الخارجي (Aider وClaude Code وCodex) داخل حاوية فقط، ولا يعمل على جهازك مباشرة أبداً.
  - حدّد صورة بإصدار ثابت: `LAYANX_AGENT_IMAGE_AIDER` (ومثلها `_CLAUDE_CODE` و`_CODEX`).
  - الحاوية ترى مجلد المشروع فقط، وتصل إلى Ollama عبر `host.docker.internal`.

## VS Code

1. شغّل LayanX، ثم ثبّت الإضافة: `powershell -ExecutionPolicy Bypass -File scripts\windows\install-vscode-extension.ps1`
2. صفحة الإعداد ← **الهاتف و VS Code** ← **إنشاء رمز ربط**.
3. في VS Code: `Ctrl+Shift+P` ← **LayanX: Connect (Pairing Code)** ← أدخل الرمز.

يُربط المجلد المفتوح في VS Code بالمشروع تلقائياً، فيقرأ الوكيل ملفاتك ويعدّلها ويختبرها داخل هذا المجلد نفسه. يأخذ المجلد نفس اسم المشروع في VS Code وZed وJetBrains. إن كان مربوطاً من قبل يُستخدم الاسم نفسه.

لا يُنقل اسم مشروع إلى مجلد آخر دون علمك، لأن مستوى الثقة والعزل يتبعان الاسم. عند ربط مجلد باسم مستخدم في صفحة المشاريع، يسألك LayanX أولاً. الأوامر: Run Goal، Build / Repair Project، Explain Selection، Fix Selection، Show Approvals (للموافقة دون مغادرة VS Code).

## Zed وJetBrains (بروتوكول ACP)

يعمل LayanX داخل محررات تدعم Agent Client Protocol، مثل Zed وIDEs من JetBrains (2026.2 وما بعده) وNeovim:
1. شغّل LayanX.
2. من صفحة الإعداد ← **Zed و JetBrains** انسخ الإعداد، وفيه مسارات جهازك جاهزة.
3. في Zed الصقه في `settings.json`. في JetBrains ضعه في `~/.jetbrains/acp.json`.

ما يحدث بعد ذلك:
- **ربط المجلد**: يُربط المجلد المفتوح في المحرر بمشروع باسمه. إن كان المجلد مربوطاً من قبل (من VS Code مثلاً) يُستخدم نفس المشروع. لا يأخذ أبداً اسم مشروع مربوط بمجلد آخر، لأن الثقة والعزل محفوظان لكل مشروع. المجلدات بأسماء عربية تأخذ اسماً ثابتاً مثل `project-1a2b3c`.
- **الطلب**: كل طلب تكتبه يصبح مهمة، وتظهر خطواتها في المحرر.
- **الموافقة**: الخطوة التي تحتاج موافقتك تظهر في المحرر: «موافقة لمرة» أو «رفض». لا يوجد خيار «دائماً»، لأن مستويات الثقة تُضبط في صفحة الإعداد فقط.
- **الاتصال**: يستخدم رمز التثبيت المحلي من الخزنة المشفرة، ويقبله LayanX من جهازك فقط.
- **خوادم MCP**: الخوادم التي يقترحها المحرر لا تُشغَّل؛ تضيفها من LayanX بموافقتك.
- **التشغيل اليدوي**: `npm run acp`. لعنوان آخر: `LAYANX_URL`. لرمز جهاز مربوط: `LAYANX_API_TOKEN`.

## التحكم بالكمبيوتر

يستطيع الوكيل: تحريك الفأرة، النقر والنقر المزدوج والأيمن، التمرير، كتابة نص بأي لغة بما فيها العربية، اختصارات مثل `CTRL+C` و`ALT+TAB` و`WIN+R`، وتصوير الشاشة. كل إجراء على الفأرة ولوحة المفاتيح يحتاج موافقتك.

**يقرأ النوافذ كقائمة بدل الصور:**
- `desktop.ui.tree` يقرأ النافذة الأمامية عبر UI Automation في Windows، ويعطي قائمة مرقّمة بالأزرار والحقول والقوائم: اسم كل عنصر ونوعه وموقعه.
- ثم يعمل على العنصر برقمه: `desktop.ui.click` للنقر، و`desktop.ui.set_text` لكتابة نص في حقل، و`desktop.window.focus` لإحضار نافذة بعنوانها.
- هذا أدق بكثير مع النماذج الصغيرة من تخمين الإحداثيات من لقطة الشاشة. الصورة تبقى احتياطاً للتطبيقات التي لا تكشف عناصرها.
- حقول كلمات المرور لا تُقرأ قيمتها أبداً.
- يبدأ المساعد بالخلفية بعد التشغيل بخمس ثوانٍ ليكون أول إجراء سريعاً. لإيقاف ذلك: `LAYANX_DESKTOP_PREWARM=off`.

ملاحظتان من Windows نفسه (والوكيل يطلب موافقتك قبل كل نقرة أو كتابة): لا يستطيع التحكم بنافذة تعمل كمسؤول (Administrator) إلا إذا شُغّل LayanX كمسؤول، ولا يعمل والشاشة مقفلة.

  - تشفير DPAPI.
  - تثبيت أدوات الأمان وتشغيلها على مشروع فيه مشاكل مزروعة.
  - Piper ينطق جملة عربية ثم Whisper يكتبها، وSilero يميز الصمت من الكلام، وSmart Turn يقيّم نهاية الجملة، وكلمة الاستدعاء تُسمع عبر Whisper.
  - العزل المقيّد: الكتابة خارج المشروع و`.git` مرفوضة، والـ pipes والعمليات الفرعية تعمل، و`npm install` ثم `npm test` ينجحان، والمهلة توقف الشجرة كلها، وحد الذاكرة يعمل.
  - جسر ACP يتصل بـ LayanX الحقيقي برمز الخزنة ويربط مجلداً.
- مهمة `zap` تشغّل ZAP الحقيقي على تطبيق فيه مشاكل مزروعة، ومهمة `evals` تشغّل حالات التقييم على نموذج Ollama صغير حقيقي.

قاعدة مهمة عند إضافة أي أداة تشغّل برنامجاً خارجياً: استخدم `safeChildEnv()` بدل `...process.env`، ولا تشغّل ملفات `.cmd` مع `shell:false` على Windows؛ استخدم `nodeToolCommand()`.

## حل المشكلات

| ما تراه | الحل |
|---|---|
| «افتح LayanX من الاختصار» | افتحه من الاختصار ليُنشأ رابط دخول جديد. |
| Port 3000 is used | أغلق البرنامج الآخر أو عيّن `LAYANX_PUBLIC_PORT=3300`. |
| المساعد لا يسمع | اسمح بالميكروفون من رمز القفل بجانب العنوان، واستخدم Edge أو Chrome. |
| «لا يوجد نموذج متاح» | شغّل Ollama وثبّت نموذجاً، ثم إعادة فحص النماذج. |
| الرد بطيء أول مرة | طبيعي: Ollama يحمّل النموذج في الذاكرة، ثم يصبح أسرع. |
| الهاتف لا يتصل من خارج المنزل | تأكد أن Tailscale متصل على الجهازين، وأن «التحكم من أي مكان» مفعّل، وأعدت التشغيل. |
| «claude returned HTTP 404» أو «model not found» | اختر نموذجاً من القائمة بعد «اختبار وعرض النماذج». |
| رابط OAuth لا يعود | سجّل عنوان العودة `http://127.0.0.1:3000/v1/oauth/callback` في تطبيقك لدى المنصة. |
| «Monthly cloud budget reached» | بلغت حد الإنفاق الشهري للسحابة؛ ارفعه من صفحة الإعداد أو انتظر الشهر التالي. |
| مهمة مستقلة «في الانتظار» | مهمة أخرى تعمل على نفس المشروع؛ تبدأ تلقائياً عند انتهائها. |
| دليل أو مهارة «بانتظار الموافقة» | جاءت مع ملفات المشروع؛ راجعها في صفحة التعلم والمهارات ووافق إن كانت سليمة. |
| «UI Automation is unavailable» | يعمل التحكم بالفأرة والصور، لكن قراءة العناصر تحتاج Windows 10/11 العادي (ليس Server Core). |
| خادم MCP لا يقبل الموافقة | ثبّت إصداراً محدداً في الأمر (مثل `@playwright/mcp@0.0.68`)؛ «latest» مرفوض. |
| «Restricted isolation runs on Windows only» | العزل المقيّد خاص بـ Windows؛ على غيره اختر «بدون سكربتات التثبيت» أو Docker. |
| `npm install` يفشل في العزل المقيّد | غالباً حزمة `file:` تشير خارج المشروع، أو حزمة تحتاج سكربت تثبيت. انقل الحزمة داخل المشروع، أو استخدم Docker. |
| «lx-sandbox: the command reached the memory limit» | ارفع `LAYANX_DOCKER_MEMORY` (مثل `6g`). |
| Zed أو JetBrains: «LayanX is not reachable» | شغّل LayanX.cmd أولاً. إن غيّرت المنفذ ضع `LAYANX_URL` في إعداد المحرر. |
| «the Arabic speech model is still loading» | نموذج Cohere يُحمَّل في الذاكرة بعد التشغيل؛ انتظر دقيقة. |
| `npm run eval`: «Ollama is not reachable» | شغّل Ollama وثبّت نموذجاً واحداً على الأقل. |
