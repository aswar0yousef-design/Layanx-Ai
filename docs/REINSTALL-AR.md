# إعادة تثبيت LayanX على Windows 11 — دليل آمن

**لا تحذف النسخة القديمة أو مجلد بياناتها قبل حفظ نسخة احتياطية.** قد تحتوي بياناتك ومفاتيح الخدمات ومشاريعك على ملفات لا يمكن استعادتها من GitHub.

## 1. احفظ بياناتك أولاً

1. أوقف LayanX من زر الإيقاف أو شغّل LayanX-Stop.cmd.
2. انسخ مجلد %LOCALAPPDATA%\LayanX إلى مكان آمن. يحتوي عادةً على السجلات والإعدادات والخزنة والبيانات المحلية.
3. انسخ أي مجلدات مشاريع أنشأتها داخل مسار العمل، ولا تنسَ المجلدات التي ربطتها يدويًا في VS Code.
4. لا ترسل ملفات .env أو secrets.dpapi أو كلمات المرور أو مفاتيح API إلى أي شخص.

## 2. نزّل النسخة الجديدة

بعد اعتماد إصدار مستقر أو PR واختباراته، نزّل ZIP من فرع الإصدار/الإصدار المنشور، ثم فكّه في مسار ثابت مثل C:\LayanX.

لا تشغّل التطبيق من مجلد Downloads المؤقت، ولا تفك نسخة فوق مجلد النسخة القديمة. إذا لم يوجد إصدار مثبت ومختبر، لا تستخدم فرع تطوير على أنه إصدار نهائي.

## 3. متطلبات التشغيل

- Windows 11 x64.
- Node.js 22 أو أحدث.
- Ollama يعمل محليًا، مع نموذج مناسب لذاكرة الجهاز.
- ميكروفون ومخرج صوت، وسماح للمتصفح باستخدام الميكروفون.
- MetaTrader 5 وPython مع حزمة MetaTrader5 فقط إذا كنت تريد اختبار MT5.
- خدمات البريد والتجارة والتواصل والإعلانات تحتاج بيانات اعتماد وموافقة OAuth خاصة بكل مزود؛ تثبيت التطبيق وحده لا يربط حساباتك.

## 4. شغّل المشغّل

1. انقر بزر الفأرة الأيمن على LayanX.cmd ثم Run إذا احتجت.
2. انتظر اكتمال التهيئة الأولى دون إغلاق النافذة.
3. افتح صفحة الإعدادات، وتحقق من أن حالة Ollama والنموذج المحلي سليمة.
4. افتح صفحة المساعد الصوتي وجرّب أمرًا قصيرًا أولًا.
5. افتح لوحة التحكم وتأكد من أن إنشاء مشروع جديد ينشئ مجلدًا منفصلًا باسم المشروع.

## 5. افحص التثبيت قبل الاستخدام

افتح PowerShell داخل مجلد LayanX وشغّل الأمر التالي:

    powershell -ExecutionPolicy Bypass -File .\scripts\windows\diagnose-install.ps1

لتشغيل فحوص TypeScript والبناء والقبول التشغيلي:

    powershell -ExecutionPolicy Bypass -File .\scripts\windows\diagnose-install.ps1 -RunChecks

لتشغيل الاختبارات الآلية أيضًا:

    powershell -ExecutionPolicy Bypass -File .\scripts\windows\diagnose-install.ps1 -RunChecks -RunTests

التقرير يُحفظ في %LOCALAPPDATA%\LayanX\logs\diagnostic-*.txt. هذه الفحوص تساعد على تحديد العطل؛ لكنها لا تثبت وحدها أن الصوت والتحكم المكتبي وMT5 والتكاملات الخارجية تعمل فعليًا.

## 6. ربط الحسابات الاجتماعية والإعلانية

1. افتح **التكاملات** ثم قسم OAuth. ستعرض الواجهة عنوان Callback المحلي الصحيح؛ انسخه حرفيًا إلى إعدادات تطبيق المطوّر لدى المزود.
2. اضبط معرّف العميل والسر وعنوان العودة الخاصين بالمزود في إعدادات LayanX المحلية. لا تضع أسرار OAuth في Git أو في محادثة.
3. ابدأ الربط وافتح صفحة موافقة المزود، ثم وافق على الصلاحيات المطلوبة. ارجع إلى LayanX وحدّث الصفحة للتأكد من ظهور الاتصال.
4. إذا ظهر خطأ، تحقق من تطابق عنوان العودة حرفيًا ومن الصلاحيات التي وافق عليها التطبيق. بعض المزودين يطلبون مراجعة التطبيق أو تفعيل صلاحيات النشر/الإعلانات قبل العمل.
5. إلغاء الربط يحذف بيانات الاتصال المحفوظة من LayanX؛ اختبر النشر والإعلانات أولًا على محتوى/حساب تجريبي أو صلاحيات قراءة فقط.

لا يعني ظهور اتصال OAuth أن النشر أو إدارة الحملات يعملان تلقائيًا. اختبر اكتشاف الحسابات ثم كل إجراء مطلوب على حدة.

## 7. تهيئة MT5 للتجربة فقط

1. افتح MT5 وسجّل الدخول إلى حساب تجريبي.
2. فعّل زر Algo Trading إذا كان مطلوبًا للاختبار.
3. في PowerShell نفّذ python -m pip install MetaTrader5 باستخدام نفس Python الذي يستدعيه LayanX.
4. شغّل أداة التشخيص وتأكد من ظهور حزمة Python وعملية MT5.
5. نفّذ اختبار قراءة الحساب والأسعار أولًا. لا تسمح بأوامر حقيقية أثناء التحقق، ولا تضع كلمات مرور الحساب في ملفات عامة أو مستودع Git.

## 8. معايير قبول الإصدار قبل حذف القديم

- npm run typecheck ينجح.
- npm test ينجح في كل ملفات الاختبار المكتشفة، مع تسجيل عدد الملفات الناجحة والفاشلة.
- npm run build ينجح.
- npm run operational:acceptance ينجح.
- تجربة صوت عربية قصيرة مع قياس زمن التفريغ والتفكير والصوت.
- إنشاء مشروعين منفصلين وإثبات أن ملفات كل مشروع لا تختلط.
- تنفيذ مهمة تطوير صغيرة مع اختبارات فعلية وتقرير نجاح/فشل.
- اختبار التحكم بالكمبيوتر على تطبيق آمن غير حساس.
- اختبار MT5 قراءة فقط ثم حساب تجريبي.
- اختبار كل تكامل خارجي بعد ربط الحساب الحقيقي المصرّح به.

**لا تحذف النسخة القديمة حتى تكتمل هذه المعايير على جهازك.**

## 8. إنشاء مجلد مستقل لكل مشروع

1. افتح لوحة الإعدادات المحلية `/setup` من نفس الكمبيوتر.
2. في قسم «مجلد مشاريعك»، اختر مجلد الجذر واضغط «حفظ». إذا غيّرت الجذر فأعد تشغيل LayanX قبل إنشاء المشاريع.
3. استخدم «إنشاء مشروع جديد». ستنشأ مجلدات فرعية منفصلة وملف `.layanx-project.json` و`README.md`.
4. إنشاء المجلد لا يعني أن المشروع قد بُني أو اكتمل؛ اكتب الهدف ومعايير القبول ثم اطلب من الوكيل التنفيذ، وافحص تقرير الاختبارات.

## 9. ربط منصات التواصل والإعلانات عبر OAuth

من لوحة التحكم افتح «التكاملات» ثم «ربط الحسابات الاجتماعية والإعلانية عبر OAuth». يلزم إنشاء تطبيق مطوّر لدى المزود وضبط معرّف العميل والسر وعنوان إعادة التوجيه المطابق في إعدادات LayanX المحلية. بعد ذلك أنشئ رابط الموافقة، وافتحه، وأكمل موافقة المزود، ثم حدّث الصفحة للتحقق من الاتصال.

وجود زر OAuth لا يعني أن كل صلاحيات النشر أو الإعلانات متاحة تلقائيًا؛ قد يحتاج التطبيق إلى مراجعة من المزود أو صلاحيات إضافية. لا تضع الأسرار في مستودع Git ولا تشاركها في المحادثة.

## 10. المهارات

الأداة `skill.recommend` ترتّب المهارات المحلية **المفعّلة والمعتمدة فقط** بحسب مدى صلتها بالهدف. لا تقوم هذه الأداة وحدها بتنزيل مهارات من GitHub أو تشغيل مهارة جديدة. أي اكتشاف خارجي أو تثبيت مهارة يحتاج مرحلة منفصلة للبحث، وفحص المحتوى والترخيص والصلاحيات، ثم المراجعة والاختبار قبل التفعيل.
