# إعادة تثبيت LayanX على Windows 11 — دليل آمن

**لا تحذف النسخة القديمة أو مجلد بياناتها قبل حفظ نسخة احتياطية.** قد تحتوي بياناتك ومفاتيح الخدمات ومشاريعك على ملفات لا يمكن استعادتها من GitHub.

## 1. احفظ بياناتك أولًا

1. أوقف LayanX من زر الإيقاف أو شغّل `LayanX-Stop.cmd`.
2. انسخ مجلد `%LOCALAPPDATA%\LayanX` إلى مكان آمن؛ قد يحتوي السجلات والإعدادات والخزنة والبيانات المحلية.
3. انسخ مجلدات المشاريع وأي مسارات ربطتها يدويًا في VS Code.
4. لا ترسل ملفات `.env` أو `secrets.dpapi` أو كلمات المرور أو مفاتيح API لأي شخص.

## 2. نزّل النسخة الجديدة

استخدم إصدارًا مستقرًا أو PR تم اعتماده بعد الفحص. فكّه في مسار ثابت مثل `C:\LayanX`، ولا تفكّه فوق النسخة القديمة أو تشغّله من مجلد Downloads مؤقت. هذا الفرع ما زال فرع تطوير، فلا تعتبره إصدارًا نهائيًا حتى يكتمل قبول الجهاز الفعلي.

## 3. المتطلبات

- Windows 11 x64.
- Node.js 22 أو أحدث.
- Ollama يعمل محليًا ونموذج مناسب لذاكرة الجهاز.
- ميكروفون ومخرج صوت وسماح للمتصفح باستخدام الميكروفون.
- MetaTrader 5 وPython وحزمة `MetaTrader5` فقط إذا أردت اختبار MT5.
- ربط البريد والتجارة والتواصل والإعلانات يحتاج بيانات اعتماد وموافقة من كل مزود؛ تثبيت التطبيق وحده لا يربط حساباتك.

## 4. شغّل المشغّل

1. شغّل `LayanX.cmd` من مجلد المشروع.
2. انتظر اكتمال التهيئة الأولى.
3. افتح صفحة الإعدادات وتحقق من حالة Ollama والنموذج المحلي.
4. جرّب أمرًا قصيرًا في المساعد الصوتي.
5. أنشئ مشروعًا تجريبيًا وتحقق من أن له مجلدًا مستقلًا.

## 5. التشخيص والفحوص

من PowerShell داخل مجلد LayanX:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\diagnose-install.ps1
```

لفحوص TypeScript والبناء والقبول التشغيلي:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\diagnose-install.ps1 -RunChecks
```

ولتشغيل الاختبارات الآلية أيضًا:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\diagnose-install.ps1 -RunChecks -RunTests
```

يُحفظ التقرير في `%LOCALAPPDATA%\LayanX\logs`. الفحوص تساعد في التشخيص لكنها لا تثبت وحدها عمل الصوت أو التحكم بسطح المكتب أو MT5 أو الحسابات الخارجية. راجع نتيجة كل فحص، ولا تتجاهل حالات FAIL.

## 6. ربط الحسابات الاجتماعية والإعلانية

1. افتح «التكاملات» ثم قسم OAuth، وانسخ عنوان Callback المعروض.
2. سجّل عنوان العودة نفسه حرفيًا في إعدادات تطبيق المطوّر لدى المزود، ثم اضبط معرّف العميل والسر وعنوان العودة في إعدادات LayanX المحلية. لا تضع الأسرار في Git أو المحادثات.
3. ابدأ الربط وافتح صفحة موافقة المزود. بعد الموافقة ارجع إلى LayanX وحدّث الصفحة للتحقق من ظهور الاتصال.
4. عند الخطأ، تحقق من تطابق عنوان العودة ومن الصلاحيات التي وافق عليها التطبيق. قد يتطلب المزود مراجعة التطبيق أو تفعيل صلاحيات النشر والإعلانات.
5. اختبر اكتشاف الحسابات ثم كل إجراء مطلوب على حدة، وابدأ بحساب تجريبي أو صلاحيات قراءة فقط. إظهار اتصال OAuth لا يعني أن النشر أو إدارة الحملات يعملان تلقائيًا.
6. Google Ads يحتاج كذلك إلى Developer Token معتمد من Google Ads API؛ OAuth وحده لا يكفي.

## 7. اختبار MT5 بأمان

1. افتح MT5 وسجّل الدخول إلى حساب تجريبي.
2. ثبّت الحزمة باستخدام نفس Python الذي يستدعيه LayanX: `python -m pip install MetaTrader5`.
3. شغّل التشخيص وتأكد من اكتشاف عملية MT5 والحزمة.
4. اختبر قراءة حالة الحساب والأسعار فقط. لا تستخدم أموالًا حقيقية ولا تسمح بتنفيذ أوامر حقيقية أثناء القبول.

## 8. مجلد مستقل لكل مشروع

1. افتح صفحة الإعدادات المحلية `/setup`.
2. اختر جذر مساحة العمل واحفظه. إذا غيّرت الجذر فأعد تشغيل LayanX قبل إنشاء المشاريع.
3. استخدم «إنشاء مشروع جديد». يُفترض أن ينشئ مجلدًا مستقلًا وملف `.layanx-project.json` و`README.md`.
4. إنشاء المجلد لا يعني أن المشروع اكتمل. حدّد هدف المشروع ومعايير قبوله ثم اطلب من الوكيل التنفيذ، وافحص الاختبارات والتقرير.

## 9. المهارات

أداة `skill.recommend` ترتّب المهارات المحلية المفعّلة والمعتمدة بحسب صلتها بالهدف. لا تقوم وحدها بتنزيل مهارات من GitHub أو تفعيل كود خارجي. يجب أن يتضمن أي اكتشاف أو تثبيت خارجي مراجعة للمصدر والترخيص والصلاحيات ثم اختبارًا قبل التفعيل.

## 10. معايير القبول قبل حذف النسخة القديمة

- `npm run typecheck` ينجح.
- `npm test` ينجح في كل ملفات الاختبار المكتشفة.
- `npm run build` ينجح.
- `npm run operational:acceptance` ينجح مع Ollama متصلًا فعلًا وبوضع التخزين المقصود.
- قياس زمن الصوت العربي من الميكروفون إلى الرد.
- إنشاء مشروعين منفصلين وإثبات عدم اختلاط الملفات.
- تنفيذ مهمة تطوير صغيرة والتحقق من البناء والاختبارات وتقرير الإكمال.
- تجربة التحكم بالكمبيوتر في تطبيق آمن غير حساس.
- اختبار MT5 قراءة فقط ثم على حساب تجريبي.
- اختبار كل تكامل خارجي بحساب مصرح به، بما في ذلك اكتشاف الحساب وتجديد الاتصال وإلغاء الربط.

**لا تحذف النسخة القديمة حتى تكتمل هذه المعايير على جهازك.** نجاح CI على خادم GitHub لا يعادل اختبار جهازك الشخصي.
